# Сценарии работы

*English version: [../en/usage.md](../en/usage.md)*

## Передать часть работы соседям

`dispatch` — это оркестрация, он не меняет код. Обязательное предусловие: изменения,
на которых строится задача, уже зафиксированы в ветке разработки.

```bash
git status --porcelain    # должно быть пусто
```

Есть незакоммиченные или неотслеживаемые изменения — агент остановится и спросит:
закоммитить или откатить. Коммиты делаются в принятом в репозитории формате;
если формат не объявлен — изменения группируются по смыслу и коммитятся по группам,
сообщения по Conventional Commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`).

```
/handoff:dispatch нужно добавить эндпоинт /v2/orders во фронт и выкатить миграцию
```

Поверх существующей задачи, заведённой человеком:

```
/handoff:dispatch 42 …
/handoff:dispatch owner/api#42 …
/handoff:dispatch https://github.com/owner/api/issues/42 …
```

## Взять задачу у себя

```
/handoff:inbox
/handoff:take 17
```

`take` ставит 👀, подтягивает контекст заказчика и приступает к работе в отдельной ветке.

## Отчитаться

Перед отчётом изменения оформляются pull request, в описании — `Closes #17`:
так PR попадает в секцию Development задачи.

```
/handoff:report
/handoff:report 17 кратко: что сделано
```

`report` публикует коммент-результат, ставит 🚀 и **закрывает задачу**.

## Задать вопрос и встать на паузу

```
/handoff:block 17 какой формат даты в ответе — ISO или unix?
```

Вопрос публикуется комментарием, задача получает 😕, ссылка на вопрос появляется
в колонке «Question» коммент-задачи. Работа останавливается.

## Проверить, ответить, завершить

```
/handoff:check
/handoff:answer owner/web#9 ISO-8601 в UTC
/handoff:accept owner/api#42
```

`answer` дописывает ответ **в тот же комментарий-вопрос** и ставит на него 👍.
`accept` закрывает задачу-родителя, если нет блокировок и все задачи-депенденты закрыты.

## Возобновить заблокированную задачу

```bash
hf question-status --ref <url-вопроса>
```

| Ответ | Что делать |
|---|---|
| `pending` | ответа нет — ждать |
| `answered` | ответ выводится тут же — продолжать работу |
| `reacted-no-answer` | 👍 есть, ответа нет — остановиться и спросить человека |

Возобновив работу, уберите ссылку на вопрос: `hf status-set --ref 17 --status WIP --clear-question`.

## Поддержание карты соседей в актуальном состоянии

Репозитории меняются, и устаревший `.handoff/external-repos.md` отправляет работу
не туда. Обновление пересобирает только то, что действительно изменилось:

```
/handoff:refresh            # обновить репозитории, у которых изменились источники
/handoff:refresh --check    # показать, что устарело, ничего не меняя
/handoff:refresh owner/web  # только один репозиторий
```

`hf doctor` предупредит, когда карта старше `HANDOFF_MAP_MAX_AGE_DAYS` (по умолчанию
30 дней), так что помнить периодичность самому не нужно.

## Ссылка на задачу

Любая команда принимает ссылку в любом виде:

| Форма | Пример |
|---|---|
| номер | `42` |
| номер с решёткой | `#42` |
| репозиторий и номер | `owner/api#42` |
| URL задачи | `https://github.com/owner/api/issues/42` |
| URL комментария | `…/issues/42#issuecomment-123` |
| текущая задача сессии | опустить или `-` |

Команда первой строкой печатает, что именно разрешилось: `→ owner/api#42`.

## Порядок в течение дня

| Роль | Утро | В течение дня | Перед концом |
|---|---|---|---|
| оркестратор | `/handoff:check` | `/handoff:answer` на блокировки | `/handoff:accept`, когда всё закрыто |
| любая роль | `/handoff:refresh`, когда doctor сообщил об устаревшей карте | — | — |
| исполнитель | `/handoff:inbox` | `/handoff:take`, работа, PR | `/handoff:report` или `/handoff:block` |

## Чего плагин делать не будет

- Коммитить за разработчика незафиксированные изменения без его решения.
- Оценивать качество чужой работы: закрытая задача считается выполненной.
- Принимать решения за человека по срокам, приоритетам, деньгам и совместимости —
  вместо этого статус BLOCKED и вопрос.
- Повторять запись после трёх конфликтов — вместо этого BLOCKED и просьба разобраться.
- Создавать задачи в репозиториях, которых нет в `.handoff/config.env`.
