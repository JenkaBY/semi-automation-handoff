# Протокол сообщений

*English version: [../en/protocol.md](../en/protocol.md)*

Версия протокола: **1**. Мажорная версия должна совпадать во всех репозиториях-участниках;
при расхождении задача не берётся в работу (код выхода 5).

## Статусы — это реакции

Лейблами статусы не обозначаются.

| Код | Эмодзи | Реакция GitHub | Кто ставит |
|---|---|---|---|
| NEW | ⬜ | *реакций нет* | по умолчанию при создании; `hf answer` при снятии блокировки |
| WIP | 👀 | 👀 `eyes` | исполнитель |
| BLOCKED | ⛔ | 😕 `confused` | исполнитель |
| DONE | 🚀 | 🚀 `rocket`, задача закрыта | исполнитель |
| CANCELLED | 👎 | 👎 `-1` | оркестратор |

GitHub допускает только восемь реакций (👍 👎 😄 🎉 😕 ❤️ 🚀 👀), среди них нет `💯`.
Поэтому DONE — это 🚀.

**Разрешение статуса**, когда реакций несколько:
CANCELLED → DONE → *задача закрыта* → BLOCKED → WIP → NEW.
Закрытая задача считается выполненной даже без реакции: выполненная задача — это закрытая задача.

👍 `+1` статусом не является: это отметка «на вопрос отвечено» на комментарии-вопросе.

## Жизненный цикл

```
NEW ──take──▶ WIP ──report──▶ DONE (исполнитель закрывает свою задачу)
 ▲             │
 │             └──block──▶ BLOCKED ──answer──▶ NEW
 └─────────────────────────────────┘
```

Приёмки как шага нет: оркестратор не оценивает качество кода. Когда нет блокировок
и все задачи-депенденты завершены, оркестратор закрывает задачу-родителя (`hf accept`).

## Коммент-задача

```markdown
<!-- handoff:routing v=1 chain=hf-20260913-a1b2 -->
## 🔀 Delegation · chain `hf-20260913-a1b2`

| Repository | Task | Status | Updated | Result | Question |
| --- | --- | --- | --- | --- | --- |
| `owner/web` | [#17](…) | 🚀 DONE | 2026-09-13 11:20 | [result](…) | — |
| `owner/infra` | [#9](…) | ⛔ BLOCKED | 2026-09-13 11:40 | — | [question](…) |

<sub>⬜ NEW · 👀 WIP · ⛔ BLOCKED · 🚀 DONE · 👎 CANCELLED — each row is updated only by the agent of that repository</sub>
```

Ключ строки — slug в первой колонке между обратными кавычками. Парсер работает по нему
и не трогает остальные строки. Колонка «Question» заполняется при блокировке и очищается
исполнителем после того, как он прочитал ответ.

## Коммент-результат

```markdown
<!-- handoff:result v=1 repo=owner/api -->
### 📦 Result · `owner/api` · 2026-09-13 11:20

## What was done
## Contracts and integration points
## What the assignee must know
## What is still missing
```

Не редактируется никогда. Новый результат — новый комментарий.

## Коммент-вопрос: вопрос и ответ в одном комментарии

```markdown
<!-- handoff:question v=1 repo=owner/web -->
### ❓ Question · `owner/web` · 2026-09-13 11:40

## What is missing
## Options
## Done before blocking

---
### 💬 Answer · 2026-09-13 12:05

ISO-8601 in UTC.
```

Ответ дописывается в тот же комментарий, отдельного комментария не заводится.
Отвечающий ставит на комментарий реакцию 👍.

| Состояние | Что означает | Действие исполнителя |
|---|---|---|
| ни 👍, ни секции «Answer» | ответа ещё нет | ждать, работу не возобновлять |
| 👍 и секция «Ответ» | отвечено | продолжать, очистить колонку «Question» |
| 👍 без секции «Answer» | противоречие | остановиться, позвать человека (код 7) |

## Задача-депендент

```markdown
**Context:** [result in owner/api#42](…#issuecomment-123) · **Status goes here:** [routing comment](…#issuecomment-124)

## Task
## Done when

<details><summary>🔗 handoff meta</summary>

```yaml
chain: hf-20260913-a1b2
key: 7f3c9a21
from: owner/api#42
context: https://github.com/owner/api/issues/42#issuecomment-123
routing: https://github.com/owner/api/issues/42#issuecomment-124
path: owner/api>owner/web
depth: 1
protocol: 1
plugin: 1.0.0
```
</details>
```

| Поле meta | Назначение |
|---|---|
| `chain` | идентификатор волны делегирования |
| `key` | идемпотентность: одна задача на пару «цепочка + репозиторий» |
| `from` | задача-родитель |
| `context` | коммент-результат — единственный источник контекста |
| `routing` | коммент-задача — куда исполнитель пишет статус |
| `path` | маршрут делегирования, защита от циклов |
| `depth` | глубина цепочки, сверяется с `HANDOFF_MAX_DEPTH` |
| `protocol` | мажорная версия протокола отправителя |
| `plugin` | версия плагина отправителя, информативно |

## Связь с кодом

Изменения связываются с задачей штатной секцией **Development**: в описании pull request
пишется `Closes #<номер задачи>`. Ссылки на ветки в комментарии и таблицу не добавляются.
`hf check` показывает привязанные PR и помечает `⚠no-PR` закрытые задачи без них.

## Запись статуса и разрешение конфликтов

1. `GET` комментария → тело и `updated_at` (версия).
2. Замена **только своей части**, остальное переносится байт-в-байт.
3. Повторный `GET`: версия изменилась → всё сначала.
4. `PATCH`.
5. Верификация `GET`.
6. Не сошлось — пауза 1с/2с/4с с джиттером, максимум три попытки.

После трёх неудач — код 75. Тогда: статус на задаче (реакция) уже выставлен и является
источником истины, задача помечается BLOCKED, конфликт разрешает человек, таблица
восстанавливается командой `hf routing-render --ref <задача-родитель>`.
